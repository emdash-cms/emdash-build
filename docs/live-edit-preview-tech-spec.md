# Edit an existing site in the draft preview

Status: implemented by `feat/live-edit-preview`; production auth follow-up based on `origin/main` at `c2d8b15`.
This document alone authorizes no implementation or Git/GitHub mutation; the accompanying request separately authorizes implementation, a worktree, and a PR.

## Production auth follow-up

The production button and credentialed cache bypass are deployed, but the Codex in-app browser reproduces one remaining boundary: `/_emdash/api/auth/dev-bypass` renders correctly in a top-level preview tab, while the same first session write inside the builder iframe returns to the anonymous page. Once that session has been established first-party, reloading the same iframe shows the EmDash toolbar. This is an embedded-cookie bootstrap issue, not a shared-preview cache hit.

Keep the fix to one first-party round trip. **Edit site** submits the existing dev-bypass GET as a top-level navigation, adding the current builder project path to the preview redirect as an internal query marker. The Worker validates that marker against the derived builder origin and `/s/<uuid>` route before injecting it into the bridge configuration, and carries it only through same-origin redirects. On the authenticated public page, the bridge immediately replaces the top-level preview with that validated builder URL. The builder then restores its existing project and remembered preview route; the credentialed iframe receives live editor HTML as it does after any established session. Project-scoped `sessionStorage` preserves an unsent composer draft or one queued message across that round trip and clears it through the existing send flow.

Do not add partitioned-cookie policy, popup coordination, durable state, a new endpoint, or an EmDash-core auth change. A failed bypass remains visible and Back returns to the builder. The marker is never trusted as an arbitrary URL, is not stored as the selected preview route, and disappears when the builder reloads the remembered route.

Acceptance is one focused commit: UI coverage proves the top-level GET preserves the current route and builder return path; bridge coverage accepts only the derived builder project URL, rejects cross-origin or non-project returns, and preserves the marker through same-origin redirects; composer coverage restores unsent and queued text; existing localhost cookie and anonymous-cache behavior stay unchanged. Run focused Vitest, `pnpm check`, `pnpm format`, and `pnpm build`, then repeat the requested adversarial review to convergence. Expected change is roughly 80-120 production lines, 80-120 test lines, and this addendum only; the expansion is limited to the two accepted review findings.

## Outcome and boundary

An owner who has finished building a site can select **Edit site** in the chat's draft preview, arrive at the same route in that iframe with EmDash's authenticated toolbar, turn on edit mode, and save an annotated field. This must work for an existing persisted project without rebuilding its scaffold or regenerating its pages, including on localhost. The normal anonymous preview remains fast and contains no editor-specific HTML.

Included: a draft-only entry point in the builder preview and correct per-viewer HTML delivery in the Sandbox preview proxy. Excluded: a second editor, automatic rewriting of previously generated pages without annotations, changes to EmDash core or authentication, editing a published/claimed site, a new API or token, and changes to the existing agent build flow. The site's own toolbar continues to own edit mode, save and publish actions.

## Verified behavior and options

- `PreviewPanel` already navigates an iframe to the EmDash dev-bypass route when opening Admin; the blank scaffold's layout retains EmDash page context and UI hooks, and the build prompt requests field annotations. The pinned scaffold uses `emdash@0.37.0`.
- EmDash's public-page middleware renders the toolbar for authenticated editors and uses the `emdash-edit-mode` cookie when its toggle is enabled. `/_emdash/api/auth/dev-bypass?redirect=<local path>` establishes the existing development session before navigating to the requested page. A page without `entry.edit.FIELD` annotations still cannot offer inline editing for that field.
- `Sandbox.fetch` currently returns a route-keyed anonymous snapshot **before** considering cookies or Authorization. It correctly refuses to _store_ an authenticated render but can still _serve_ the anonymous one to an editor; the toolbar and edit-mode rendering disappear. Its credentialed cache-miss path already seeds an anonymous snapshot separately.
- A `localhost` builder and `*.localhost` preview are cross-site to the browser. EmDash's `astro-session` and `emdash-edit-mode` cookies default to `SameSite=Lax`, so neither reaches the iframe. A live Chrome probe confirmed that `SameSite=None; Secure` cookies on the HTTP `.localhost` preview are sent in its iframe; a local new-tab fallback does not meet the in-chat requirement.
- Replacing the cache with per-user entries is unnecessary and risks leaking editor HTML. Disabling snapshots globally loses the current preview latency protection. Switching EmDash toolbar modes would not repair this proxy-level cache hit. Keep the shared snapshot only for uncredentialed requests.

## Design

1. Show one **Edit site** button only after the initial build's existing `complete` milestone, on a ready draft Site tab. Disable it until the current page's bridge reports in, including during navigation. It navigates the same iframe through the existing dev-bypass endpoint, with the current normalized route (including query/fragment) passed as the encoded local `redirect`. Do not treat the transient auth page as the selected site route. No token is exposed to page code or query parameters. The Admin tab, live target, and pre-setup preview do not show the action.
2. On public document GET/HEAD requests carrying a Cookie or Authorization, bypass the shared snapshot lookup and send them to the existing live Sandbox proxy. Keep the current rule that no credentialed response is stored as a shared snapshot; retain the anonymous background seed on a credentialed cache miss. Uncredentialed hits, stale revalidation, assets, API calls, WebSockets, and the preview bridge retain their current behavior.
3. Only for HTTP `*.localhost` preview responses, change the `astro-session` Set-Cookie attributes to `SameSite=None; Secure`, preserving HttpOnly and unrelated cookies. Only in the injected localhost preview bridge, follow EmDash's edit-toggle change event and overwrite its edit-mode cookie with those same attributes (or clear it when toggled off). Production, deployed sites, and scaffold source retain their existing behavior; neither cookie value is sent to the builder parent.
4. The EmDash toolbar handles entering/leaving edit mode, field changes, saves and publication. The builder iframe remains on the current route. A failed dev-bypass or failed render remains visible rather than silently falling back to an anonymous snapshot. Track the document leaving on each edit attempt (the public page, or an auth error page on retry); preserve the attempt across that document's `beforeunload`, then clear it when any later document departs. If the auth frame finishes loading without a public-page bridge report, re-enable **Edit site** so the owner can retry on the same route. Ordinary navigation remains disabled until its bridge reports. No new durable state is added.

The `redirect` is confined to a normalized same-origin path; the existing dev-bypass handler validates it again. Existing session cookies and EmDash's editor role decide whether editing is actually allowed. The shared snapshot is never populated by an editor response. Credentialed navigation may be slower than anonymous last-known-good HTML, but only while that viewer needs a private render; no extra per-user cache/storage or periodic work is introduced.

Local browser boundary: the in-frame flow was verified in Chrome and the Codex in-app browser. Safari before 27 does not accept `Secure` cookies over plaintext HTTP loopback and blocks third-party cookies; supporting that local configuration would require a same-site dev hostname or HTTPS **plus** partitioned cookies or a Storage Access flow, outside this focused change. HTTPS alone would not make a cross-site iframe first-party. Production builder/preview hosts share a site and do not need this localhost exception.

## Evidence and acceptance

- A regression test seeds a public snapshot and requests that route as both an anonymous and a credentialed visitor: anonymous receives the snapshot; Cookie and Authorization receive the live render, and no private body is written into the shared row. A credentialed miss still seeds only an anonymous render.
- UI tests start at a non-root route in a completed draft, activate **Edit site**, and observe a dev-bypass iframe URL whose decoded redirect is that exact route; the action is absent before build completion, in Admin, and on the live target, disabled during navigation, and retryable after an auth frame fails to reach a public page. Localhost also stays inside that iframe and opens no tab.
- Cookie tests verify local session attributes, preservation of unrelated cookies, unchanged production headers, and localhost-only bridge injection. Manual smoke with a real local Sandbox and CMS must edit an annotated field **inside the chat iframe**, observe PUT 200, reload the iframe to see the draft, and separately verify an anonymous visit still receives published text. If no local Sandbox is available, report this as an unverified integration boundary rather than claiming end-to-end success.
- Run focused Vitest, `pnpm check`, formatting, and the affected Worker/SPA build. No database migration, generated scaffold files, dependency update, or production deployment.
